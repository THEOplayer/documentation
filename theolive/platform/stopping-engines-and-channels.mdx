# Stopping engines and channels

You can stop an engine, or all engines of a channel at once, in two ways:

- **Stop** ends the stream for viewers and then shuts the engine down gracefully. This is the default, and the right choice in almost every case.
- **Force stop** tears the engine down immediately, without ending the stream cleanly. Use it when the engine has to be gone at once, or to cut short a stop that is still in progress.

## Stop

A stop ends the stream before the engine goes away. The engine closes its playlists (an HLS media playlist gets an `EXT-X-ENDLIST` tag), so players reach the end of the stream instead of running into a playback error. The engine then shuts down: it reports `stopping` for about 10–20 seconds, then `stopped`.

## Force stop

A force stop skips the graceful shutdown: the engine is torn down right away, without closing its playlists. Players keep waiting for new segments that never come, so viewers may see playback stall or fail instead of the stream ending. The engine reports `stopping` for a few seconds, then `stopped`.

A force stop works from any state except `stopped`, including while the engine is still `stopping` after a regular stop.

## Rules

- **An engine can only be started again once it is `stopped`.** While it is `stopping`, starting it fails with `409 already_playing`. Starting a channel only starts the engines that are `stopped`, so an engine that is still `stopping` is skipped: wait until the channel is `stopped` before you start it again.
- **Stopping an engine that is already `stopping` force stops it.** Calling stop a second time on an engine or a channel therefore has the same effect as a force stop.
- **An engine in `error` is always force stopped.** It has no stream left to end, so a stop tears it down right away.
- **Stopping or force stopping a `stopped` engine fails** with `409 already_stopped`.
- **A channel stop covers the whole channel.** Stopping or force stopping a channel does the same to all its engines and to its RTSP pull ingests.

The status of a channel is derived from its engines, and the most active engine state wins: a channel with one `playing` and one `stopping` engine is `playing`. A channel is only `stopping` once all its engines are `stopping` or `stopped`.

[Schedulers](./scheduler.mdx) and the channel's ingest timeout stop engines gracefully, the same way as a stop.

## API

| Action     | Engine                                   | Channel                                    |
| ---------- | ---------------------------------------- | ------------------------------------------ |
| Stop       | `POST /v2/engines/{engineId}/stop`       | `POST /v2/channels/{channelId}/stop`       |
| Force stop | `POST /v2/engines/{engineId}/force-stop` | `POST /v2/channels/{channelId}/force-stop` |

All four return `204` as soon as the request is accepted; the engines then shut down in the background. Follow their progress through the `status` of the [engine](../api/get-engine.api.mdx) or [channel](../api/get-channel.api.mdx), or through [webhooks](#webhooks).

### API example — [Stop a channel](../api/stop-channel.api.mdx)

`POST https://api.theo.live/v2/channels/{channelId}/stop`

```bash
curl -X POST https://api.theo.live/v2/channels/ch_abc123/stop \
  -H "Authorization: Basic $AUTH"
```

### API example — Force stop a channel

`POST https://api.theo.live/v2/channels/{channelId}/force-stop`

```bash
curl -X POST https://api.theo.live/v2/channels/ch_abc123/force-stop \
  -H "Authorization: Basic $AUTH"
```

### API example — [Stop an engine](../api/stop-engine.api.mdx)

`POST https://api.theo.live/v2/engines/{engineId}/stop`

```bash
curl -X POST https://api.theo.live/v2/engines/eng_ghi789/stop \
  -H "Authorization: Basic $AUTH"
```

### API example — Force stop an engine

`POST https://api.theo.live/v2/engines/{engineId}/force-stop`

```bash
curl -X POST https://api.theo.live/v2/engines/eng_ghi789/force-stop \
  -H "Authorization: Basic $AUTH"
```

## Dashboard

In the [dashboard](https://dashboard.optiview.dolby.com/), every stop button opens a dialog that lets you choose between a stop and a force stop:

- **Engine:** the stop button of an engine opens the **Stop engine** dialog, with **Stop** and **Force stop**.
- **Channel:** **Stop channel** on the channel details page, and **Stop all engines** in the channels table, open the **Stop all engines** dialog, with **Stop all** and **Force stop all**.

While an engine or a channel is `stopping`, the graceful option is gone: its stop button becomes **Force stop** (**Force stop channel** on the channel details page, **Force stop all engines** in the channels table), and the dialog only offers the force stop. The start button of an engine only returns once the engine is `stopped`.

## Webhooks

Each way of stopping sends the [engine webhook events](./real-time-update-with-webhooks.mdx#engine-events) at different moments:

| Stopping                                           | `engine.stopping`               | `engine.stopped`                                  |
| -------------------------------------------------- | ------------------------------- | ------------------------------------------------- |
| Stop                                               | When the stop is accepted       | Once the engine is torn down, about 10–20 s later |
| Force stop                                         | When the force stop is accepted | Once the engine is torn down, a few seconds later |
| Stop or force stop of an engine that is `stopping` | Not sent again                  | Once the engine is torn down, a few seconds later |
| Stop of an engine in `error`                       | When the stop is accepted       | Once the engine is torn down, a few seconds later |

`channel.stopped` is sent when a stop or force stop of the channel is accepted, while its engines may still be shutting down. To know when an engine is gone, wait for its `engine.stopped`.
