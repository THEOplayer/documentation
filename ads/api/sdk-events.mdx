# OptiView Ads SDK events

The [OptiView Ads SDK](/ads/player-integration/optiview-ads-sdk/) emits events throughout the ad lifecycle so your application can react to what the viewer sees. Events exist to let you:

- **Build your own UI** — show a countdown before a break, hide the player controls while ads play, and restore them afterwards.
- **Track playback and analytics** — forward break, ad, and quartile events to your analytics backend.
- **Monitor errors and buffering** — observe ad or content playback issues without polling the player.
- **Keep your app state in sync** — know at any moment whether content or an ad is on screen.

All platforms (Web, Android, iOS, React Native) expose the **same event types** with equivalent payloads — only the subscription idiom differs per platform. Every event includes a `type` string and a `timestamp` (milliseconds since epoch).

## Event reference

| Event             | When it fires                                                                                    | Key payload fields                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `adbreakstatus`   | The break state or countdown changed — an upcoming warning, active break progress, or completion | `status` — an `AdBreakStatus` object (see below)                             |
| `adbreakbegin`    | An ad break starts and content is paused                                                         | `break`, `format`, `tuneIn?` (present only when the viewer joined mid-break) |
| `adbreakend`      | The ad break ends and content resumes                                                            | `break`, `format`                                                            |
| `adbegin`         | An individual ad starts playing                                                                  | `break`, `format`, `asset`, `adIndex`, `totalAds`, `adId?`, `creativeId?`    |
| `adend`           | An individual ad finishes                                                                        | `break`, `format`, `asset`, `adIndex`, `totalAds`, `adId?`, `creativeId?`    |
| `aderror`         | Playback fails — non-fatal for ads, the SDK recovers and content resumes                         | `source` (`'ad'` \| `'content'`), `error`, `break?`, `format?`, `asset?`     |
| `adfirstquartile` | An ad reaches 25% completion                                                                     | `break`, `format`, `asset`, `adIndex?`, `totalAds?`                          |
| `admidpoint`      | An ad reaches 50% completion                                                                     | `break`, `format`, `asset`, `adIndex?`, `totalAds?`                          |
| `adthirdquartile` | An ad reaches 75% completion                                                                     | `break`, `format`, `asset`, `adIndex?`, `totalAds?`                          |
| `adtimeupdate`    | On each time update tick during ad playback (about 4 times per second)                           | `break`, `format`, `asset`, `currentTime`, `duration`                        |
| `waiting`         | Playback stalls for buffering                                                                    | `source` (`'ad'` \| `'content'`), `break?`, `asset?`                         |
| `playing`         | Playback (re)starts after stalling or pausing                                                    | `source` (`'ad'` \| `'content'`), `break?`, `asset?`                         |
| `volumechange`    | The SDK's unified mute/volume state changed (**Web only** today)                                 | `muted`, `volume`                                                            |

A few things to know:

- **`waiting`, `playing`, and `aderror` fire for both content and ad playback.** Check the `source` field to tell them apart.
- **Break- and ad-scoped events carry `format`** — the [layout](/ads/concepts/breaks#layouts) of the break's selected variant (`single`, `double`, `lshape_ad`, `lshape_content`, `overlay`). Use it to branch your UI, for example a distinct treatment for an L-shape versus a full-screen ad.
- **`adbegin` and `adend` always balance.** Every `adbegin` is followed by exactly one `adend`, even when a break reaches its maximum duration and the SDK cuts an in-flight ad short to return to content.
- **Google Ad Manager pod-served ads emit the same lifecycle** — `adbreakbegin → adbegin → adend → adbreakend`, with the quartile events firing during playout. On Web, a pod filled with several creatives reports one `adbegin`/`adend` pair per real ad, so `adIndex`/`totalAds` describe the pod's true composition.

## The `AdBreakStatus` object

The `adbreakstatus` event is the recommended way to drive countdowns and break-related UI. Its `status` object contains:

| Field               | Description                                                       |
| ------------------- | ----------------------------------------------------------------- |
| `phase`             | `'idle'`, `'upcoming'`, `'active'`, or `'complete'`               |
| `secondsUntilBreak` | Seconds until the next break starts (during the `upcoming` phase) |
| `breakRemainingSec` | Seconds remaining in the active break                             |
| `adsRemaining`      | Number of ads left in the break                                   |
| `adIndex`           | Index of the currently playing ad                                 |
| `totalAds`          | Total number of ads in the break                                  |
| `ticking`           | Whether the countdown is actively progressing                     |

You can also query the current status at any time with `sdk.getAdBreakStatus()`. To receive `upcoming` warnings ahead of a break, configure `breakWarnings` on the SDK — for example `breakWarnings: { seconds: [10, 5] }` emits `adbreakstatus` with `phase: 'upcoming'` at 10 and 5 seconds before the break.

## Subscribing to events

Subscribe with `sdk.addEventListener(type, handler)` and unsubscribe with `sdk.removeEventListener(type, handler)`:

```typescript
// Break boundaries — hide your controls during the break
sdk.addEventListener('adbreakbegin', (e) => {
  console.log(`Break ${e.break.id} started (${e.break.duration}s, format: ${e.format})`);
  hidePlayerControls();
});
sdk.addEventListener('adbreakend', () => {
  showPlayerControls();
});

// Countdown UI — drive a "break starts in Xs" toast
sdk.addEventListener('adbreakstatus', (e) => {
  if (e.status.phase === 'upcoming') {
    showToast(`Ad break in ${e.status.secondsUntilBreak}s`);
  }
});

// Individual ads and quartiles — feed your analytics
sdk.addEventListener('adbegin', (e) => {
  console.log(`Ad ${e.adIndex + 1} of ${e.totalAds} — asset ${e.asset.id}`);
});
sdk.addEventListener('admidpoint', (e) => {
  trackMidpoint(e.asset.id);
});

// Errors — covers both ad and content playback (check e.source)
sdk.addEventListener('aderror', (e) => {
  console.error(`[${e.source}]`, e.error.message);
  // For ad errors the SDK recovers automatically — content resumes
});
```

To unsubscribe, keep a reference to the handler:

```typescript
const handler = (e) => console.log(e);
sdk.addEventListener('adbreakbegin', handler);
// Later:
sdk.removeEventListener('adbreakbegin', handler);
```

Subscribe with `addEventListener(event, handler)` using the `OptiViewAdsEventType` enum. Events are a sealed class hierarchy — cast to the concrete subtype to read the payload. Note the break property is named `break_` (Kotlin reserves `break`):

```kotlin
// Break boundaries
sdk.addEventListener(OptiViewAdsEventType.ADBREAKBEGIN) { event ->
    val e = event as AdBreakBeginEvent
    Log.d("Ads", "Break ${e.break_.id} (${e.break_.duration}s)")
}

// Individual ads
sdk.addEventListener(OptiViewAdsEventType.ADBEGIN) { event ->
    val e = event as AdBeginEvent
    Log.d("Ads", "Ad ${e.adIndex + 1}/${e.totalAds} — asset ${e.assetId}")
}

// Errors — covers both ad and content (check source); the SDK recovers for ads
sdk.addEventListener(OptiViewAdsEventType.ADERROR) { event ->
    val e = event as AdErrorEvent
    Log.e("Ads", "[${e.source.value}] ${e.error.message}")
}
```

To unsubscribe, keep a reference to the handler:

```kotlin
val handler: OptiViewAdsEventListener = { event -> Log.d("Ads", "$event") }
sdk.addEventListener(OptiViewAdsEventType.ADBREAKBEGIN, handler)
// Later:
sdk.removeEventListener(OptiViewAdsEventType.ADBREAKBEGIN, handler)
```

`addEventListener(_:_:)` returns a `Subscription` token; pass it to `removeEventListener(_:_:)` to unsubscribe. Events are a Swift `enum` with associated values — `switch` on the case to read the payload, or use the convenience accessors (`event.type`, `event.source`, `event.breakId`, `event.assetId`, `event.format`):

```swift
// Break boundaries
sdk.addEventListener(.adbreakbegin) { event in
    if case let .adBreakBegin(brk, _, tuneIn, format) = event {
        print("Break \(brk.id) [\(format?.rawValue ?? "?")]")
    }
}

// Individual ads
sdk.addEventListener(.adbegin) { event in
    if case let .adBegin(_, assetId, adIndex, totalAds, _, _) = event {
        print("Ad \(adIndex + 1)/\(totalAds) — asset \(assetId)")
    }
}

// Errors — covers both ad and content (check source); the SDK recovers for ads
sdk.addEventListener(.aderror) { event in
    if case let .adError(source, _, _, error, _, _) = event {
        print("[\(source.rawValue)] \(error.localizedDescription)")
    }
}
```

To unsubscribe, keep the returned token:

```swift
let token = sdk.addEventListener(.adbreakbegin) { event in print(event.type.rawValue) }
// Later:
sdk.removeEventListener(.adbreakbegin, token)
```

  <TabItem value="react-native" label="React Native">

Subscribe on the ads instance with `addEventListener(type, handler)`, the same idiom as on Web. The ad lifecycle runs natively, so events keep flowing even while the JavaScript thread is paused or throttled (for example in Picture-in-Picture) — they are buffered and delivered when JavaScript resumes:

```tsx
const ads = createOptiViewAds(player, {});

ads.addEventListener('adbreakbegin', (e) => {
  console.log(`Break ${e.break.id} started`);
  setControlsVisible(false);
});
ads.addEventListener('adbreakend', () => {
  setControlsVisible(true);
});
ads.addEventListener('aderror', (e) => {
  console.error(`[${e.source}]`, e.error.message);
});

await ads.startSession({ manifestUrl: MANIFEST_URL });
```

To unsubscribe, keep a reference to the handler and pass it to `removeEventListener(type, handler)`.
