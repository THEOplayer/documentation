# Events

An event is a channel-scoped time window that groups the ad breaks belonging to one scheduled occurrence, such as a live game, a show, or a tournament. It gives you a single handle for the breaks around that occurrence: an event lists the breaks that fall inside its window. Breaks are not tied to an event by id, so creating, moving, or deleting an event never changes a break.

An event can also [replace the channel's integrations](#integrations-during-an-event) for its duration, for example to send the breaks of one game to its own Google Ad Manager live stream while the rest of the 24/7 channel keeps the channel's.

Events also anchor the [break punching](./breaks.mdx#break-punching) workflow: ahead of a live occurrence you prepare a break without a start time, and during the broadcast you fire it at the exact moment.

## Event identity

Every event has an `id` that is unique within its channel. The `id` is optional when creating an event: if you omit it, OptiView Ads generates one for you. When you supply your own, we recommend using a UUID. For a human-readable label, use the `name` property instead — it is shown in the dashboard.

## Time window

An event is defined by a `startDate` and an `endDate`, both UTC ISO 8601 timestamps. `startDate` must be before `endDate`, and the events of a channel cannot overlap. Events are only available on live channels with the `wallclock` [timebase](./channels.mdx#timebase).

The window is how an event finds its breaks: `GET /channels/{channelId}/events/{eventId}/breaks` returns the breaks of the channel whose start falls inside the window — `startDate` inclusive, `endDate` exclusive. The window is not enforced on breaks: a break is never validated against an event, and a break that starts inside the window may run past the event's `endDate`.

## Breaks under an event

Breaks carry no reference to an event. An event resolves its breaks from its time window:

- A break scheduled on the timeline belongs to the event whose window contains its `start`.
- A [cued break](./breaks.mdx#cued-breaks) has no start yet. While it waits to be punched, it is listed under the event that is in progress at the time of your request. Once punched, it belongs to the event whose window contains its start.
- [Event-triggered breaks](./breaks.mdx#event-based-triggers) — pre-roll, pause, and post-roll — have no position on the timeline and are listed under every event of the channel.

Because the lookup is purely time-based, a break can exist on the channel without falling under any event, and a break automatically shows up under a new event whose window covers its start.

:::note[Deleting an event keeps its breaks]
Deleting an event removes only the event. Its breaks stay on the channel and keep being served to players; they simply no longer appear under that event.
:::

## Integrations during an event

The [integrations](../integrations/index.mdx) of a channel are its defaults: they apply around the clock. An event can replace them with integrations of its own for the duration of its window — for example a different Google Ad Manager live stream, or no integration at all.

Event integrations take the same body as channel integrations and are managed under the event:

```text
/channels/{channelId}/events/{eventId}/integrations
```

The event's `overridesIntegrations` decides which integrations apply while the event is active:

- **`false`** (default) — the channel integrations apply. Integrations stored on the event are kept but have no effect.
- **`true`** — the event integrations replace the channel integrations as a whole. Nothing is taken from the channel: an event without integrations runs without any.

Like a channel, an event holds at most one integration per `type` and `vendor`. Google asset keys only have to be unique across channel integrations, so event integrations may reuse them — every game of a season can point at the same Google live stream.

Event integrations are copies, not references: changing the channel integrations does not affect an event that overrides them. Deleting an event deletes its integrations.

A break uses the integrations in effect at its `start`, so a break that starts inside the event's window uses the event's. A [cued break](./breaks.mdx#cued-breaks) has no start yet and uses the integrations in effect when it is cued, so cue it once the event has started. Players switch configuration at the event's boundaries on their own: the [Break Manifest](./break-manifest.mdx#events) announces each event ahead of time.

### Delivery and ad start delay

An event can also replace two channel settings for its window. Both fall back to the channel's value when omitted.

- **`delivery`** — the [delivery rules](../workflows/index.mdx#hybrid-ad-insertion-sgai-and-ssai) that steer devices to SGAI or SSAI, replacing the channel's rules as a whole.
- **`adStartDelay`** — the seconds of playback before any break may start, for sessions that start during the event.

## Event templates

An event template is an organization-level preset for events you run repeatedly, such as every game of a season. It holds the ad configuration of an event — its integrations, `delivery`, and `adStartDelay` — and is managed under `/templates/events`.

The integrations of an event template are referenced through `integrationTemplateIds`. An integration template, managed under `/templates/integrations`, is a named integration body that can be reused across event templates:

```json
{
  "id": "season-pod-serving",
  "name": "Season pod serving",
  "type": "SGAI",
  "vendor": "GOOGLE",
  "customAssetKey": "season-2026-games"
}
```

```json
{
  "id": "league-game",
  "name": "League game",
  "integrationTemplateIds": ["season-pod-serving"]
}
```

Create an event from the template by passing its `templateId`:

```bash
curl -X POST 'https://us.ads.optiview.dolby.com/api/v1/channels/1f7f3a5a-9c2e-4a56-b1d4-3f8a2c9d6e01/events' \
  -u "$ADS_API_KEY:$ADS_API_SECRET" \
  -H 'Content-Type: application/json' \
  -H 'X-Org-ID: org_123' \
  -d '{
    "templateId": "league-game",
    "name": "Week 5",
    "startDate": "2026-11-01T18:00:00.000Z",
    "endDate": "2026-11-01T21:30:00.000Z"
  }'
```

Each integration template is copied onto the event as an event integration, and `overridesIntegrations` is set to `true` when the template lists integration templates. Omit `integrationTemplateIds` to create events that keep the channel integrations, or set it to `[]` for events that run without any. Fields in the request win over the template.

Like [break templates](./templates.mdx#snapshot-semantics), an event template is a snapshot: editing it later does not change events already created from it. Its optional `channelIds` only filter the template list; any channel can create events from it.

## Break templates for an event

[Break templates](./templates.mdx) can be linked to one or more events through their `eventIds`, so a reusable break preset can be surfaced for quick scheduling under those events. Instead of creating your breaks before the event, prepare templates ahead of time and schedule breaks from them during the event.

## Break punching during an event

For a live occurrence you usually do not know the exact break times in advance, but you want the break fully prepared so it can fire instantly. This is what [break punching](./breaks.mdx#break-punching) is for:

1. Create the event with a window that covers the occurrence, for example kickoff through the final whistle.
2. Ahead of the occurrence, create the [templates](./templates.mdx) describing the breaks you want to run.
3. During the event, create a cued break from a template, without a `start`. OptiView Ads prepares it (including any ad decisioning) and it waits in the `CUED` state.
4. Punch the break whenever it needs to go — for example, at half-time. Its start is set and it is announced to players right away.
5. Repeat for the next break: cue it from a template, then punch it at the right moment.

A channel holds only one cued break at a time, so punch the current cued break before cueing the next one. Do not delete a cued break unless you have cued the wrong one.

Because a punch uses the current time as the break's start, punch a cued break while the event is in progress: its start then falls inside the event's window, so the break is listed under the event.
