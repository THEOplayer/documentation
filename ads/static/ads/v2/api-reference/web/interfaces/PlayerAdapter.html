    Interface PlayerAdapter

    The abstraction layer between the SDK and any video player. The core only talks to players through this interface; each player gets its own adapter package.

    Example

    class HlsJsAdapter implements PlayerAdapter {
      constructor(private hls: Hls, private video: HTMLVideoElement) {}
      // ... implement all methods
    }

    ReadonlycurrentTime

    currentTime: number

    Current playback time in seconds.

    Readonlyduration

    duration: number

    Content duration in seconds; may be Infinity for live streams.

    Optional ReadonlyisLive

    isLive?: boolean | null

    Whether the content is LIVE, as the engine itself understands it.

    Exists because !Number.isFinite(duration) — the obvious proxy, and what the SDK used everywhere before this — is simply WRONG on hls.js. hls.js only sets the media duration to Infinity for live when liveDurationInfinity is configured, and that defaults to false; otherwise a live stream reports a finite duration equal to the playlist edge. Measured on the NFL Channel feed 2026-08-24: a genuinely live hls.js session was refused as not-live, and the legacy continuous-playout mode never engaged for a whole break.

    maxLiveSeekPosition is not a substitute either — hls.js derives it from latestLevelDetails, which exists on VOD too, so it is non-null there.

    Every engine knows the answer authoritatively, so ask it rather than infer:

    engine source
    hls.js hls.latestLevelDetails.live (no EXT-X-ENDLIST)
    shaka player.isLive()
    THEOplayer duration === Infinity — it really does report that for live

    null means the adapter cannot say, and callers fall back to the duration proxy — which keeps older adapters working exactly as they did, bug included, rather than silently flipping their behaviour. Same convention as maxLiveSeekPosition: null is a real answer, not a gap.

    Optional ReadonlymaxLiveSeekPosition

    maxLiveSeekPosition?: number | null

    The furthest position a seek will actually STICK on live content (seconds on this timeline) — the engine quietly pulls back anything closer to the live edge — or null when unknown or not live. Return null when unsure: the SDK then does NOT clamp, and a guessed holdback can place content worse than no clamp. Computed engine-side as currentTime + currentLiveOffset - minimumOffset (hls.js liveSyncPosition; THEOplayer latencyManager.currentLatency / minimumOffset; shaka seekRange().end - currentTime / safeSeekEndOffset; ExoPlayer getCurrentLiveOffset() / minOffsetMs; AVPlayer seekableTimeRanges / configuredTimeOffsetFromLive).

    muted

    muted: boolean

    Settable so the SDK can sync mute state between content and ad players.

    Readonlypaused

    paused: boolean

    Whether the player is paused.

    OptionalplaybackRate

    playbackRate?: number

    Playback rate (1 = normal). Optional, settable. Used to take drift out of content playing HIDDEN behind an ad (continueContentDuringBreak), where a forward seek would be clipped at seekable.end. MUST report what the ENGINE has, not the last write: live engines run their own latency controller on this property (hls.js maxLiveSyncPlaybackRate, THEOplayer, Shaka liveSync) and the SDK detects being overridden by comparing. Undefined: drift is reported, not corrected.

    ReadonlyprogramDateTime

    programDateTime: Date | null

    Program Date Time (HLS EXT-X-PROGRAM-DATE-TIME) for wallclock break matching; null if unavailable.

    Optional ReadonlyseekableEnd

    seekableEnd?: number | null

    Where the media ENDS (seconds), or null; distinct from maxLiveSeekPosition by the engine's holdback. The <video> element is unreliable: THEOplayer reports seekable.end() as Number.MAX_SAFE_INTEGER while player.seekable has the real DVR window, so a guard reading the element passed every target. If undefined the core falls back to videoElement.seekable and rejects sentinel values.

    Optional ReadonlysourceUrl

    sourceUrl?: string | null

    Optional: the MANIFEST URL this adapter is playing (not the element's src, which is a blob: on MSE engines). Lets the SDK lend the media element to an ad and give it back (shared-element path: the only way into a Safari PiP window, and how iOS reaches its AVPlayerLayer). Read it from the ENGINE, not from the last load() argument: applications may load through the engine directly. null opts out (DA-SHARED-ELEMENT-UNSUPPORTED).

    Optional ReadonlysupportsParallelBuffering

    supportsParallelBuffering?: boolean

    Optional capability hint: can content and ad pipelines buffer in parallel without decoder contention? false prevents continued content playout during a break. Undefined counts as capable.

    Optional ReadonlyvideoElement

    videoElement?: HTMLVideoElement | null

    The underlying HTMLVideoElement, if any. Required for GAM (the IMA SDK needs the element).

    volume

    volume: number

    Volume in [0, 1]; settable so the SDK can sync it between content and ad players.

    Optionalpreload

    • preload?(url: string): Promise<void>

      Optional: warm caches (manifest, optionally the first fragment) WITHOUT attaching media or engaging a decoder, for single-decoder Smart TVs that cannot hold two MediaSources. Must not call attachMedia(). Leave undefined if unsupported; the SDK loads on demand at break start.

      Parameters

      • url: string

      Returns Promise<void>

    OptionalreleaseMediaElement

    • releaseMediaElement?(): void | Promise<void>

      Optional: stop driving the <video> element without giving it up. Shared-element path only: the SDK plays the ad through the CONTENT element, and two engines holding it fought over the MediaSource on Safari + Shaka (ad aborted or looped on ~half of breaks). Must NOT tear down: the SDK hands the element back with load() at break end. hls.js swaps in place and may leave it undefined.

      Returns void | Promise<void>

    OptionalsetVideoQuality

    • setVideoQuality?(quality: "lowest" | null): boolean

      Optionally select a content quality, or pass null to release the SDK's override. A successful lowest request snapshots the integrator's current selection and applies the cheapest rendition without flushing buffered media. Returns whether the request was applied; passing null restores the exact prior selection.

      Parameters

      • quality: "lowest" | null

      Returns boolean

    Optionalunload

    • unload?(): void

      Optional: release the held media (detach MediaSource / clear the source) without destroying the adapter; the next load() re-attaches. Called on single-decoder TVs when a break ends, BEFORE content resumes: a still-attached MediaSource keeps the only hardware decoder and content dies with MEDIA_ERR_DECODE. Parallel-preload platforms are never asked.

      Returns void
